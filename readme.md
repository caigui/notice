# notice 提醒系统

统一入口：`main.bat`（Windows）。所有钉钉提醒共用 `dingtalk_utils.py` 的 `DingTalkNotifier`，
默认 12:30–13:00 静默窗口内不发送；`send_alert()` 会 @所有人，
市场简报 / 美股 ETF 日报用 `send_markdown(..., at_all=False)` 不 @。
微信通道（`wechatPublicCountSendMessage.py`）配置了但 `appid/appsecret` 为空且从未被调用，等于未启用。

---

## 一、启动与调度

双击 `main.bat` 后依次做四件事：

1. **自动寻找 Python**：优先本机装有 `akshare` / `prompt_toolkit` 的 Python 3.13，
   其次 PATH 中的 `python`，最后 `py -3`。原脚本硬编码的
   `WindowsApps\python3.13.exe` 路径在本机已不存在，已修复。
2. **market_brief 启动后执行一次**：后台最小化启动 `market_brief\main.bat`，
   采集 19 项市场数据并按表格推送钉钉（详见 `market_brief/README.md`）。
3. **注册 im1000 每日任务**：用 `schtasks` 幂等注册（同名覆盖）每日 **15:00**
   的 Windows 计划任务 `NoticeIm1000DailyUpdate`，执行
   `im1000\run_update.bat /auto`（`im1000_panel.py --update`）。
   `/auto` 跳过原脚本末尾的 `pause`，输出写入 `im1000\im1000_update.log`。
   **注意：im1000 只更新数据并写本地日志，没有任何对外提醒。**
4. 前台运行 `main.py`，挂载 7 个常驻 asyncio 策略任务。启动记录写 `notice_launch.log`。

> Linux 环境仍可用 `main.sh`（cron 示例 09:14 启动、15:00 kill）。Windows 下不要直接运行它。

## 三、规则有效性评估

判断分三档：**【有效】**逻辑与数据均成立、值得保留；**【存疑】**逻辑成立但有实现缺陷或时效问题；
**【无效】**当前不会触发、结果错误或已过期，建议停用/重写。

### 3.1 结论速览

| # | 提醒 | 结论 | 一句话理由 |
|---|---|---|---|
| 1 | 新债 | 【存疑】 | 逻辑对，但无跨天去重，同一标的会连推多天 |
| 2 | 新股 | 【存疑】 | 同上；日期靠 `date_field[33:42]` 硬切片，HTML 一变即失效 |
| 3 | 待发转债更新 | 【有效】 | 抢权前置信息，逻辑清晰；仅缺去重 |
| 4 | 指数调整日期 | 【无效】 | 硬编码 2026 年四个日期、只比月日，2026-11-30 后永久失效 |
| 5 | QDII 套利 | 【存疑】 | 溢价方向判断正确，但实时源失效、只剩滞后 T-1 数据 |
| 6 | ETF 套利 | 【无效】 | 变量作用域错误导致比较对象恒为最后一只，且阈值低于交易成本 |
| 7 | 场内货基套利 | 【存疑】 | 规则是经典套利，但数据源 URL 含死时间戳、无空表检查 |
| 8 | 股票事件机会 | 【有效】 | 要约价隐含价差有真实套利价值，数据可用且去重完善 |
| 9 | 可转债 | 【无效】 | 取数调用被注释、数据恒空，三条规则一条都不会触发 |
| 10 | 美股 ETF 日报 | 【有效】 | 平均溢价率是有效市场情绪参考；但属日报、非即时套利信号 |
| 11 | 市场数据速览 | 【有效】 | 指标汇总有价值；但无去重、部分源失败会留空 |

### 3.2 逐条分析

**1–3. 新股 / 新债 / 待发转债**
- 逻辑：申购日前提前提醒（打新）、关注方案已过会的转债（抢权配债），方向都是真实低风险机会，**规则本身有意义**。
- 缺陷一（严重）：没有跨天去重。窗口是「今天 ~ +5 天」，同一标的会连续 6 天进入窗口；
  又受 10/12/14 点门控，一天可命中多次。实际会重复推送同一条几十次。
- 缺陷二：新股日期靠 `date_field[33:42]` 固定切片解析集思录 HTML，页面结构一变就失效（旧解析已被注释）。
- 建议：按「代码+类型+申购日」落状态文件，同日只推一次；日期解析改用正则/表格列定位。

**4. 指数调整日期**
- 硬编码 `2026/2/28、5/31、8/31、11/30`，且比较条件为
  `date.month == today.month and date.day - today.day in range(0,11)`。
- 问题：① 注释写「2025」却填 2026，代码已过期；② 只比月、用「日相减」判断，
  跨月场景（如月末最后交易日）会漏报；③ 2026-11-30 之后表中再无 12 月日期，**永久不再提醒**。
- 结论：当前已接近失效，建议改按指数公司的实际调整公告日取数，或至少把日期表外置成配置。

**5. QDII 套利**
- 正面：溢价 >+1% 且「非暂停申购」才提示高溢价（能申购才有套利空间）、
  负溢价不看申购状态（折价可买），方向判断是对的；限购标的排前也合理。
- 缺陷：① 实时溢价依赖 `woody` 的 webdriver，驱动版本错配后取数返回 **0 条**，
  实际只剩集思录 T-1 溢价率（滞后一天），套利信号时效性大打折扣；
  ② 集思录游客接口每次仅 20 条，覆盖不全；③ `fund_purchase_em()` 在构造时只取一次，
  一旦失败会导致整个 main 启动崩溃；④ 涨幅 >8% 对 QDII 而言阈值偏高、触发稀少。
- 结论：方向正确但数据链条不可靠，修复 woody 取数后才谈得上实用。

**6. ETF 套利**
- 致命 bug：循环里用 `n['current']` 逐行赋值，但循环结束后 `n` 是**最后一只**基金；
  随后的 `abs(当前-单位净值 - n['current'])` 和溢价计算都复用这个最后值，
  导致所有行的比较对象错误——结果不可信。
- 另外阈值 0.0001（0.01%）远低于 ETF 买卖价差与手续费，即使算对也全是噪声；
  代码注释自认「TODO 可删除，没有用」。
- 结论：建议直接停用；若要保留，需修正作用域、改用实时 IOPV 并把阈值提到覆盖交易成本之上。

**7. 场内货基套利**
- 规则是经典策略：货基溢价 ≥0.3% 或买入赎回/申购卖出年化 >1.5%，确实存在无风险套利空间，**规则有意义**。
- 缺陷：① 数据源 `crawl/trade_money_fund.py` 的 URL 含硬编码时间戳，可能返回过期数据；
  ② 取数失败返回空 DataFrame，策略直接取列会 KeyError；③ 无去重，持续触发就每 50 分钟重复推。
- 建议：修 URL、加空表检查、加每日去重。

**8. 股票事件机会提醒**
- 最有价值的一条：配债抢权、要约收购（自动解析 `notes` 里的要约价并算现价隐含价差）、
  私有化/吸收合并都是可执行事件套利；数据来自交易所 snap 接口，实测可用。
- 去重完善：同「代码+类型」每自然日一次，状态跨进程持久化，发送失败不落标记。
- 局限：触发仍依赖手工维护的 `price_min/price_max` 区间；对要约收购而言，
  更本质的信号是「现价 vs 要约价 − 成本」，固定区间未必跟得上价格变化。

**9. 可转债提醒**
- 设计本身合理（日内价格波动、转股溢价率异动、负溢价），负溢价对已公告强赎的用 −0.5% 阈值也专业。
- 但实现上 `loop_check()` 把前两条的取数与检查**全部注释**，只留负溢价检查；
  而负溢价所需的数据 `cbInfo.cbCprInfo` 初始化为空列表、刷新调用同样被注释 →
  `check_negative_premium_rate()` 每次都在空表判断处直接 return。
- 结论：**三条规则实际一条都不会触发**。若要启用，恢复 `get_all_cb_info()`、
  `get_cb_cpr_info()` 两个取数调用和注释掉的检查即可，改动很小。

**10. 美股 ETF 折溢价日报**
- 给出样本平均溢价率、中位数、溢价/折价只数，是观察 QDII 额度松紧与情绪的有效参考，
  清单还做了美股 ETF 筛选（剔 LOF / 非美股），思路正确。
- 定位是「每日快照」而非套利触发（无阈值、每天固定推一次），且溢价率优先取 woody 实时值、
  缺失回落集思录 T-1，仍有滞后可能。
- 结论：作为信息日报有价值，但不要当作即时套利信号。

**11. 市场数据速览**
- 19 项指标一次汇总，信息价值明确；`safe_fetch` 对失败源降级并在正文标注缺失项，设计稳健。
- 缺陷：无去重，重复启动 `main.bat` 会重复推送；部分数据源（东财/legulegu）在本机网络下经常失败，
  报表可能缺项。

**全局问题（影响所有提醒）**
- `date_utils.is_trading_time()` 第 4 行直接 `return True`、`is_past_1500()` 恒 `False`，
  导致主程序与监控策略 7×24 小时运行，非交易时段做无意义轮询，15:00 自停逻辑也失效。
- 去重覆盖不全：只有「股票事件」和「美股 ETF 日报」有跨天状态文件，其余 8 类均无。
- 硬编码 webhook / secret / 账号密码 / SendKey 散落多处，存在泄露风险。

## 六、已知限制 / 建议

- `date_utils.is_trading_time()` 与 `is_past_1500()` 目前硬编码 `True` / `False`（见第三节全局问题）。
- 浏览器驱动版本错配（2026-11-23 实测）：本机 `msedgedriver` 只支持 Edge 151（实际 158），
  `chromedriver` 只支持 Chrome 147（实际 157）。集思录已降级匿名取数；woody 实时溢价仍依赖
  chromedriver，版本错配时返回空数据但不再清空已有缓存。恢复完整数据需更新对应 driver。
- 主进程与各策略的异常日志按「同一异常 5 分钟一次」限流；启动记录见 `notice_launch.log`，
  诊断日志见 `main_py_run_20261123.log`（原始）、`main_py_final_20261123.log`（修复后）。
- 集思录游客接口每次只返回 20 条 QDII 数据；需要全量时要有效 cookie 或匹配的浏览器 driver。
- 项目中多处存在硬编码的 webhook / 账号 / cookie / sendkey，建议改为环境变量或独立配置文件，
  并不要把密钥提交到公开仓库。
- 所有提醒统一走钉钉；如需换通道，只需改 `dingtalk_utils.py` 的发送实现。
